# Bob: Maintained File Map & Metadata Verification

## Overview

This maintenance document details the metadata file configuration, runner discovery mechanisms, and path verification for the `bob` practice exercise in the Java track as part of Task R58-T008.

---

## File Roles Declared in `.meta/config.json`

The Exercism test runner, automated check scripts, and CI workflows do not guess files or heuristically scan directories by matching class names. Instead, they strictly parse the top-level `files` object declared in `exercises/practice/bob/.meta/config.json`:

| Role | Configured Path | Purpose & Lifecycle |
|---|---|---|
| `solution` | `src/main/java/Bob.java` | **Learner Starter Implementation Stub**: Unsolved template provided to learners. Throws `UnsupportedOperationException` until implemented. Must remain pristine in the working tree. |
| `test` | `src/test/java/BobTest.java` | **Canonical JUnit 5 Test Suite**: Contains 26 behavioral test cases specifying Bob's conversational contract. Compiled into the test source set. |
| `example` | `.meta/src/reference/java/Bob.java` | **Maintained Reference Implementation**: Complete, correct reference solution used for track maintenance, automated grading, and regression verification. |
| `invalidator` | `build.gradle` | **Build Invalidation Trigger**: Exercise-specific Gradle build script. Modifications to this file invalidate cached build and test outputs. |
| `editor` | *(Optional / Not declared)* | Supported role for auxiliary non-solution source files shown in the in-browser editor (e.g. custom data structures or helper classes). When present, must resolve inside the exercise root. |

## Runner Path Resolution & Discovery Mechanism

### How the Runner Finds `BobTest.java` and `Bob.java`

1. **Deterministic Discovery via `.meta/config.json`**:
   The runner reads `exercises/practice/bob/.meta/config.json` and accesses `config["files"]["test"]` and `config["files"]["example"]`. It never scans the filesystem with wildcard patterns or heuristics.
   
2. **Path Sanitization & Containment Check**:
   Every entry in `files` is treated as a relative path anchored at `exercises/practice/bob/`. The runner verifies that:
   - Paths are relative (rejecting leading `/` or drive specifiers).
   - Paths do not contain parent directory traversal (`..`) escaping the exercise boundary.
   - The resolved absolute path has `exercises/practice/bob/` as its prefix (`candidate.relative_to(exercise_root)`).
   - The target file actually exists on disk.

3. **Compilation & Execution Source Sets**:
   - For **learner test execution**: The test runner compiles `files.solution` (`src/main/java/Bob.java`) and `files.test` (`src/test/java/BobTest.java`) under standard Gradle source sets (`src/main/java` and `src/test/java`).
   - For **reference verification**: The runner copies the exercise directory to an isolated scratch location, copies `files.example` (`.meta/src/reference/java/Bob.java`) into scratch `src/main/java/Bob.java`, un-disables all test methods in scratch `src/test/java/BobTest.java`, and executes `./gradlew test --no-daemon`. The working-tree learner starter stub remains completely untouched.

## Deliberate Negative Metadata Fixtures

The verification suite explicitly validates that any deviation from the containment contract is strictly rejected:

1. **Missing Reference Fixture**:
   - Injects `.meta/src/reference/java/MissingReference.java` into `files.example`.
   - **Result**: Rejected with `example: missing file`.
2. **Missing Test Fixture**:
   - Injects `src/test/java/MissingTest.java` into `files.test`.
   - **Result**: Rejected with `test: missing file`.
3. **Outside-Exercise Traversal Fixture**:
   - Injects `../../README.md` into `files.solution` or `files.editor`.
   - **Result**: Rejected with `path escapes exercise`.
